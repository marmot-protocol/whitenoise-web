# White Noise design system — consolidated September 2026

The live reference is `/design-system`. It uses the same tokens and components as the website, rather than a separate approximation. The consolidation replaces near-duplicate page values with a compact shared system.

## Sources of truth

- `runtime.ts`: generated browser constants for breakpoints and copy feedback; avoids shipping token documentation on ordinary pages.
- `tokens.json`: named colors, typography values, spacing, widths, grids, geometry, layers, icon sizes and motion. Each token records its purpose, consumers, and status. CSS dimensions use rem; documentation converts to pixels at the default 16px root. There are eight theme-aware color roles plus three fixed inverse-surface roles, eight size steps, four weights, four line heights, three tracking values, fourteen spacing steps and eight composition relationships.
- `typography.json`: nine complete shared type roles plus their responsive overrides. `typography.ts` adds semantic Text roles to these same rules. Element semantics and visual role are independent.
- `tokens.css` and `typography.css`: generated outputs. Edit the catalogs, then run `bun run tokens:generate`. Do not hand-edit these files.
- `icons.ts`: the only active Carbon icon imports, plus the shared two-line `MenuIcon.svelte` glyph and user-provided `theme-toggle-icon.svg`. Icons inherit text color; Icon supplies the shared size. Icons are decorative inside controls with accessible names.
- `artwork.ts`: shared bounds and visual-mass normalization, backed by generated `artwork-measurements.json`. Image geometry is source data, not a spacing scale. Artwork normalizes transparent assets without modifying their pixels.
- `primitives.css`: shared component structure and states. `src/site.css` composes the existing pages using tokens. `reference.css` styles only the reference page.

## Rules for implementation

1. Choose a documented semantic role and existing spacing token before adding a value. Four pixels (0.25rem) is the spacing base. The scale represents distances, not a visible decorative grid.
2. Do not add literal colors, font sizes, spacing, dimensions or arbitrary Tailwind values in page/component styles. Breakpoint literals are the documented 640/900px contract because CSS variables cannot be used in media queries. Zero, percentages, intrinsic layout keywords and measured SVG/artwork geometry are structural values.
3. No `legacy-space-*` values remain in live styles. Use shared heading/body, copy/action, column, section and surface inset relationships. At breakpoints these relationships change once, centrally. Do not override the same relationship per page.
4. Use the established system for every UI change. If something different is needed, explain the exact proposed difference and ask the user before implementing it. New tokens, roles, icons, visual primitives, arbitrary values, one-off overrides, and changes to established token values require explicit approval. Once approved, document the purpose, consumers and review status, regenerate styles, inspect the specimen and affected pages, then run the checks. Ordinary composition with existing system elements needs no additional approval. Renaming an old arbitrary value is not justification for a new token.
5. Keep Manrope self-hosted. Keep brand geometry intact. Use the icon registry, not new inline icon approximations.
6. State changes are immediate cuts: no fades, resizing, moving elements, keyframes or smooth scrolling. The three-second copy confirmation is a state duration, not an animation.
7. Preserve native semantics, visible keyboard focus, selectable donation addresses and responsive wrapping. Never test donation links by initiating a payment.

## Homepage artwork balance — approved September 13, 2026

Homepage Artwork instances explicitly select `normalization="visual-mass"`; the default `bounds` mode preserves Contribute and Download. Both retain the existing 1103:939 frame, desktop 400px height, mobile 22rem width cap, breakpoints and copy spacing. On desktop the frame center aligns with the complete copy block, including its optional link. On stacked layouts the frame follows the copy. The measured baseline is shared; the explicitly approved optical adjustments below are stored centrally in `artworkOpticalAdjustments`.

For each pixel with alpha above 16, weight is `(alpha / 255) × (1 − 0.92 × grayscale)`, where grayscale uses CSS sRGB coefficients 0.2126, 0.7152 and 0.0722. This measures the existing filtered sculpture composited on white. Sum weights for mass, and weighted pixel-center coordinates for the optical center. This is a repeatable perceptual proxy, not a guarantee of equal subjective prominence.

Use the talking pair's previous rendered mass as the ceiling. For each centered subject, compute its largest uniform scale that contains the measured bounds within the existing 1rem inset. The common target is the minimum of the ceiling and all feasible masses. Every scale is `sqrt(target / source mass)`; every weighted center maps to the frame center. Work in reference rem units so the inset is 16px at the default desktop frame and scales proportionally on smaller frames. Do not apply an unreviewed individual fit correction after normalization: it would break equal mass. Near-transparent export noise below the threshold is excluded from measurements; pixels are not rewritten.

Run `bun run artwork:measure` after replacing an asset or changing rendering tokens. Requires Python 3 and Pillow with WebP support; set `ARTWORK_PYTHON` to a Python executable with Pillow if the default Python lacks it. `bun run artwork:measure --check` recomputes without writing. Commit the generated measurements with the assets; Vitest checks source hashes and token parity so stale data fails validation. Runtime imports the small measurement record, never Pillow or the token documentation catalog. Inspect the seven guided specimens at `/design-system#ds-artwork`, followed by actual homepage rows at desktop, tablet, mobile, 320px and 200% zoom.

Size follow-up: the user approved a 20% enlargement through `--artwork-scale: 1.2` on desktop, then extended the same enlargement to mobile. Apply it at every viewport to the entire normalized frame around its optical center, preserving internal containment, relative visual mass and layout spacing. The reference guides enlarge with the artwork. Bounds-mode illustrations are unaffected.

Optical review follow-up: children with the plant use an additional 1.05× scale; the woman with the balloon uses 1.05 × 1.025 (another 2.5% on her already enlarged size), both about their measured center. Smith and chain shifts left from the original measured center by 5% of frame width above 900px and 10% at 900px and below, with no extra scaling or vertical shift. These replace the earlier 15% trial. Desktop placement is in the SVG viewBox; compact CSS translates the SVG by the remaining 5% of its frame width, using a value derived from the same optical-adjustment registry. Only visual-mass mode receives these corrections. The shared 1.2× enlargement still applies at every viewport. The baseline measurements and other illustrations remain unchanged; the reference specimens display the same corrections. The final adjusted set intentionally departs from exact equal measured mass to improve perceived balance.
